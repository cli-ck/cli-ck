# Scripted Browser Control via a Shared Injectable Bridge

We decided to give the AI two script-based browser-control tools — `browser_execute` against the app's own dev-preview iframe, and `browser_automate` against a real, separate, non-headless Chrome instance via CDP (`chromiumoxide`) — built on one shared injectable JS bridge (`preview_bridge.js`) rather than two separate locator implementations. The bridge exposes a small locator mini-language (`css:`, `xpath:`, `text:`, `role:name[...]`, `testid:`) and click/fill/wait/read primitives, injected via Tauri's all-frames initialization script for the iframe surface and via CDP's `evaluate_on_new_document` for the real-Chrome surface — the same "run before any page script" guarantee on both. `browser_automate` attaches to the user's already-installed Chrome rather than bundling a Chromium, and always launches visibly, never headless, so automated browsing is never silent.
